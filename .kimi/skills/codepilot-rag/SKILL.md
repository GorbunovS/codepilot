# CodePilot RAG — навигация по проекту

> Настройка для пользователя: замени `<CODEPILOT_DIR>` ниже на путь, где
> склонирован репозиторий codepilot (там лежат бинарь `codepilot`, `models/`,
> `bin/`, `docker-compose.yml`).

## Инициализация (полный стек: pgvector + e5 + Laya)

**1. MCP-сервер.** Инструменты доступны, только если сервер прописан в
конфиге агента (`~/.kimi-code/mcp.json`). Если инструментов
`mcp__codepilot__*` нет — попроси пользователя добавить блок и начать
новую сессию:

```json
{
  "mcpServers": {
    "codepilot": {
      "command": "<CODEPILOT_DIR>/codepilot",
      "args": ["serve", "--project", "<КОРЕНЬ_ПРОЕКТА>",
               "--store", "pg", "--embed", "onnx", "--laya", "onnx"]
    }
  }
}
```

**2. Инфраструктура (проверить один раз, всё на хосте, не в контейнере):**

```bash
docker compose -f <CODEPILOT_DIR>/docker-compose.yml up -d db   # Postgres+pgvector
ls <CODEPILOT_DIR>/models/e5-small          # эмбеддер; нет — <CODEPILOT_DIR>/scripts/download_models.sh
ls <CODEPILOT_DIR>/models/laya-multilingual # Laya ONNX; нет — см. README codepilot
```

**3. Индекс проекта** (обязательно с теми же флагами, что у serve):

```bash
<CODEPILOT_DIR>/codepilot index <КОРЕНЬ_ПРОЕКТА> --store pg --embed onnx
```

Индексация инкрементальная (по sha256 файлов): после изменений кода повтори
команду — пересчитаются только изменённые файлы и их векторы. Ключ проекта
в Postgres — абсолютный путь корня, поэтому все команды запускай с хоста
и с одним и тем же путём.

## Инструменты

В проекте поднят MCP-сервер `codepilot` (команда запуска:
`codepilot serve --project <корень проекта> --store pg --embed onnx --laya onnx`).
Он отдаёт 4 инструмента:

- `search_code(query, top_k)` — семантический поиск по коду (гибрид
  BM25+вектор+реранк). Возвращает топ чанков с метаданными и флагом
  `need_more`. Если `need_more: true` — уточни запрос (добавь доменные
  слова, имя модуля) или дочитай контекст через `read_span`.
- `get_symbol(name)` — определение символа (файл, диапазон строк,
  сигнатура, doc).
- `find_references(name)` — места использования символа.
- `read_span(file, start, end)` — точные строки файла.

## Правила экономии токенов

1. **Сначала `search_code`, а не чтение файлов.** Файл целиком читай
   только если поиск промахнулся дважды.
2. Вопросы «где/почему/кто вызывает» — это `search_code` /
   `find_references`, а не grep по всему репозиторию.
3. Нужен конкретный фрагмент — `read_span(file, start, end)` по
   координатам из результатов поиска, а не весь файл.
4. Следи за `need_more`: он означает, что слой решений не уверен в
   достаточности контекста — расширь запрос, прежде чем делать выводы.
5. Если поиск уверенно промахнулся (релевантного нет в топ-5 после
   переформулировки) — разрешён fallback на обычные grep/read.
